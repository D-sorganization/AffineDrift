\section{Which Dimension Is Being Reduced?}

A golf model can have many mechanical states but a small number of adjustable
commands. Those are different statements. Write a continuous-time model as
\begin{equation}
  \dot x=f(x,u),\qquad x\in\mathbb R^n,\quad u\in\mathbb R^m.
\end{equation}
Here $n$ is the local state dimension and $m$ is the input dimension. Joint
coordinates and velocities often supply mechanical states, but activation,
fiber length, estimator states, and flexible modes can add others. Quaternion
coordinates and constraints require a distinction between stored coordinates
and independent local dimensions (Volume~III). Thus $n=2\,\mathrm{DOF}$ is not
a universal model identity.

A fixed input parameterization $u=Wc$, with $W\in\mathbb R^{m\times k}$,
changes the adjustable input dimension to at most $\operatorname{rank}W\le k$.
The state still obeys $\dot x=f(x,Wc)$ in $n$ dimensions. A task output
$y=h(x)\in\mathbb R^p$ describes what is scored or observed; it need not
provide a closed $p$-dimensional dynamics. A valid reduced state model needs
additional invariance, closure, or approximation conditions and an error
bound appropriate to the task. Low-rank fitted muscle activity alone supplies
none of these guarantees.

\section{What the Computational Curse Actually Says}

For a tensor-product grid with $M$ values on each of $n$ independent state
axes, there are $M^n$ grid sites~\cite{Bellman1961}. One double-precision value
per site requires $8M^n$ bytes, before actions, transitions, interpolation,
or multiple time slices. At $M=10$, $n=6$ already requires eight million
bytes; $n=10$ requires eighty billion. This is a storage count, not a runtime
estimate. FLOPS alone cannot establish feasibility: wall time, operations per
update, memory, action discretization, and accuracy must also be specified.

Sampling does not have one universal dimension law. For independent samples
of a fixed integrand with finite variance, the sample-mean variance is
$\operatorname{Var}(F)/N_s$. The familiar $N_s^{-1/2}$ root-mean-square rate
has no explicit dimension exponent, but the variance and cost per sample can
depend on dimension. Learning an unknown policy or covering a state space is
a different problem. Its complexity depends on regularity, function class,
exploration, noise, and the requested error; a blanket polynomial guarantee
for reinforcement learning is unjustified.

Trajectory methods exploit temporal and algebraic structure instead of
covering every state. Their performance is conditional too. In a dense local
quadratic backward pass, let $A$ be $n\times n$, $B$ be $n\times m$, and $P$
be an $n\times n$ value Hessian. Products such as $A^TPA$, $B^TPA$, and
$B^TPB$, together with an $m\times m$ control solve, motivate the proxy
\begin{equation}
 C_{\mathrm{dense}}=H(n^3+n^2m+nm^2+m^3),
 \label{eq:ch2:dense-proxy}
\end{equation}
for $H$ stages. Coefficients are deliberately omitted: this is an operation
scaling proxy, not an exact flop count or measured benchmark. Derivative
construction, line search, constraints, full DDP dynamics curvature, sparse
factorizations, and implementation choices change the cost. Direct collocation
has its own sparse nonlinear-program structure; it cannot be assigned this
formula without examining its solver. Neither family is the only scalable
approach to every deterministic problem.

Replacing $m$ by $k$ in this proxy retains the $Hn^3$ term and the need to
represent state curvature. There is no general flat $O(k^3)$ cost curve as the
body dimension increases. For $n=4$, $m=2$, $H=10$, the proxy is 1200; setting
$k=1$ gives 850, while the $Hn^2=160$ stored stage-Hessian entries are unchanged.
Actual implementations can store fewer matrices; this count refers to retaining
one dense state Hessian per stage.

\begin{lstlisting}[language=Python, caption={Conditional Counts, Not Runtime Benchmarks}]
import math


def planning_costs(n_state, n_control, horizon=100,
                   grid_points=10):
    """Return counts for positive integer dimensions/stages."""
    values = (n_state, n_control, horizon, grid_points)
    if any(isinstance(v, bool) or not isinstance(v, int)
           or v < 1 for v in values):
        raise ValueError("Use positive Python integers")
    if grid_points < 2:
        raise ValueError("At least two grid points per axis")
    n, m = n_state, n_control
    return {
        "log10_grid": n * math.log10(grid_points),
        "value_hessian_entries": horizon * n**2,
        "dense_proxy": horizon * (
            n**3 + n**2*m + n*m**2 + m**3),
    }
\end{lstlisting}

The logarithmic grid count remains representable for ordinary large dimension
inputs; an arbitrary cutoff such as declaring every $n>10$ infinite would
confuse practical cost with mathematical overflow. Python integer proxy counts
do not overflow at a fixed machine-integer width. Neither property makes a
large optimal-control problem tractable.

\section{Structure Can Help Without Erasing the Body}

\begin{description}[style=nextline]
  \item[Synergies.] A restricted command basis can regularize estimation and
  reduce policy search. Its rank, task fit, and lost actuator authority must
  be checked; there is no universal four-synergy description of all muscles.
  Coefficient constraints can reduce the reachable input set further.
  \item[Hierarchy.] Separating task selection, estimation, and feedback can
  make design manageable. Their parts remain coupled by the body, measurements,
  constraints, and delays.
  \item[Passive dynamics.] Gravity, inertia, elasticity, and contact can carry
  a useful motion, reducing required intervention or work in a specified
  task. They also propagate disturbances and can destabilize motion. A useful
  drift field does not by itself reduce state or input dimension.
  \item[Prediction.] A forward model can support state estimation and feedback
  despite delay. Prediction is not restricted to open-loop execution, and its
  usefulness depends on model error and uncertainty (Chapters~3 and~6).
  \item[Task coordinates.] For a regular task map, perturbations in
  $\ker Dh(x)$ preserve the output to first order at that instant. They can
  still change contact, joint loading, future output, or constraint feasibility.
  Task-insensitive variation is not an unlimited safe space.
\end{description}

\section{A Hidden Unstable Mode}

Consider the fully actuated system
\begin{equation}
 \dot x=\begin{bmatrix}-1&0\\0&1\end{bmatrix}x+I_2u.
\end{equation}
With $u=-2x$, both eigenvalues are negative. Restricting commands to
$u=(c,0)^T$ leaves $\dot x_2=x_2$, regardless of how $c$ is chosen. Scoring
only $y=x_1$ can therefore report success while $x_2(t)=e^t x_2(0)$ diverges.
The example demonstrates a possible loss, not a theorem that every reduction
in input rank destroys controllability: dynamic coupling can preserve
controllability with fewer inputs.

For golf, clubhead delivery is a low-dimensional task description, but pelvis,
trunk, limb, club, and contact states jointly determine whether that delivery
remains feasible. A concise command representation is valuable when it retains
the corrections needed for those coupled dynamics. The right empirical
comparison holds the task and disturbances fixed, reports tracking, loading,
actuator limits, and robustness, and measures computational cost. Counting
synergy coefficients cannot substitute for that comparison.

\section*{Exercises}
\begin{enumerate}
 \item Compute the largest integer $n$ permitting one $M=10$ value grid in
 a budget of $8\times10^9$ bytes. State why this does not yet certify a dynamic
 programming calculation. (The storage bound gives $n=9$.)
 \item For $n=40$, compare $m=20$ with $k=5$ in
 Eq.~\eqref{eq:ch2:dense-proxy}, keeping $H$ fixed. Identify the unchanged terms
 and distinguish coefficient count from independent actuator authority.
 \item Derive the unstable-mode example and construct a coupled two-state,
 one-input system whose controllability matrix has rank two.
 \item Benchmark a chosen trajectory solver over chain sizes. Report state,
 input and constraint dimensions, derivative method, tolerance, hardware,
 iteration counts, and wall time. Test a scaling hypothesis rather than
 requiring a predetermined cubic result.
\end{enumerate}
