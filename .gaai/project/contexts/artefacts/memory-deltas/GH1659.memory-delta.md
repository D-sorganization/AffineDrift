# GH1659 Memory Delta

## Memory Alignment Check

No new architectural decisions emerged. The pattern applied is consistent with existing
project conventions: use `warnings.warn(UserWarning)` to signal prototype/incomplete
implementations rather than silently proceeding or using comments alone.

## Notable Pattern (low novelty — for Discovery awareness)

**Pattern:** When a module contains a known non-functional or incomplete implementation
that must remain in the codebase (e.g., as a structural placeholder), use
`warnings.warn(message, UserWarning, stacklevel=2)` at the entry point to ensure all
call sites receive an explicit runtime notification. Pair with a module-level string
constant for the warning message so tests can assert on content without string duplication.

This pattern is already implied by the "no print() in src/" rule and the logging
conventions, but the `warnings` module approach for prototype-gating was not previously
documented explicitly.

## Recommendation to Discovery

Low-priority: consider adding a sentence to `conventions.md` about using
`warnings.warn(UserWarning)` for prototype-gating incomplete implementations.
