# GH1658 Memory Delta

## New Patterns Worth Persisting

### Pattern: `batch_convert` — Shared Batch Conversion Loop

When two or more converter scripts share the same dry_run/try-except conversion loop pattern:
- Extract to `src/tools/utils/conversion_utils.py::batch_convert(converter, file_pairs, dry_run, logger)`
- Signature is stable: any converter object with a `convert_file(source, target)` method works
- file_pairs: `Iterable[dict]` with at minimum `"source"` and `"target"` string keys

### Pattern: Patch Target for `batch_convert` in Tests

When testing callers of `batch_convert`, patch `os.path.exists` at the utility module level:
```python
patch("src.tools.utils.conversion_utils.os.path.exists", return_value=...)
```
Not at the caller module level (the caller no longer owns the `os` import for file checks).

This was a straightforward DRY extraction. No new libraries, services, or paradigm shifts.
