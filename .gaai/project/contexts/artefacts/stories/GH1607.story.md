# GH1607: Repair deploy and E2E pipeline around generated docs assets

**Source:** D-sorganization/AffineDrift#1607

## Description

## Problem
`Deploy Website` is failing on `Verify frontend asset sync` because it expects mirrored files under `docs/`, while the repo comments and CI logic also state that rendered HTML/docs artifacts are generated during deploy and are not committed.

Separately, the PR E2E job skips smoke tests when `docs/index.html` is absent, so browser checks are not reliably exercised before deployment.

## Evidence
- Recent deploy runs are failing on main.
- Latest failure: `gh run view 23139269592 -R D-sorganization/AffineDrift --log-failed`
- Failure reports missing mirrors such as `docs/css/startup-launcher.css`, `docs/js/metrics.js`, and `docs/styles.css`.
- `ci-standard.yml` E2E job skips when `docs/index.html` is missing.

## Why this matters
The repo currently has a green core CI lane but a persistently red deployment lane, and its browser smoke tests are conditional on build artifacts that are not produced in PR validation. That weakens confidence in the site actually being deployable.

## Proposed fix
- Make deploy build the docs/site artifacts before sync validation, or update sync validation to check the canonical source tree instead of generated mirrors.
- Update E2E to run against a generated local build artifact instead of requiring committed `docs/index.html`.
- Keep deploy and E2E using the same build path to avoid drift.

## Acceptance criteria
- `Deploy Website` passes on main.
- E2E smoke tests run against generated artifacts in CI instead of skipping by default.
- Asset-sync expectations match the repo's documented build model.
