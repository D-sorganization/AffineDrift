# GH1667: generate_sample_torque uses hardcoded indices (250, 200, 300) assuming fixed array length

**Source:** D-sorganization/AffineDrift#1667

## Description

## Assessment: P3. Reversibility / P7. Magic Numbers

**Finding:** `src/tools/wrist_universal_joint/torque_calculator.py` `generate_sample_torque()` (lines 155-188) uses hardcoded array indices:
- Line 161: `torque[250:] = 3.0` (Step signal assumes array length > 250)
- Line 164-165: `pulse_start = 200`, `pulse_end = 300` (Pulse assumes length > 300)
- Line 169: `burst_center = 250`, `burst_width = 50`

These assume the default `DEFAULT_SIGNAL_LENGTH = 500` but will silently produce wrong results if the time array length changes.

**Impact:** The function signature accepts any time array but the implementation assumes a specific length. Changing signal length would require updating magic numbers in multiple places.

**Fix:** Compute indices relative to `len(t)`:
- `midpoint = len(t) // 2`
- `pulse_start = int(0.4 * len(t))`, `pulse_end = int(0.6 * len(t))`

**File:** `src/tools/wrist_universal_joint/torque_calculator.py:155-188`
