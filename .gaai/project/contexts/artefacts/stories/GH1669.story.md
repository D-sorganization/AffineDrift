# GH1669: Streamlit app executes code at module import level

**Source:** D-sorganization/AffineDrift#1669

## Description

## Assessment: N. Scalability / K. Data Handling

**Finding:** `src/tools/wrist_universal_joint/streamlit_app.py` executes UI code at module level (lines 47-52, 409-412):
```python
st.set_page_config(...)
if "polynomial_expression" not in st.session_state: ...
# ... and at the end:
_inject_custom_css()
_render_header()
_params = _render_sidebar()
_render_main_content(_params)
```

This means importing the module causes side effects (Streamlit rendering). It prevents:
- Unit testing individual functions in isolation
- Using the module in non-Streamlit contexts
- Lazy loading

**Impact:** Cannot import helper functions without triggering the full Streamlit app.

**Fix:** Wrap the module-level code in a `def main():` function and add `if __name__ == "__main__": main()` guard, or `if st.runtime.exists():` guard.

**File:** `src/tools/wrist_universal_joint/streamlit_app.py:47-52,409-412`
