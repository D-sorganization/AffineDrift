# GH1665: SwingOptimizationResult.__post_init__ has vacuous checks (len >= 0 always true)

**Source:** D-sorganization/AffineDrift#1665

## Description

## Assessment: P8. Design by Contract

**Finding:** In `src/affine_control/swing_optimizer.py` lines 181-187, the `SwingOptimizationResult.__post_init__` contains:
```python
require(len(self.optimal_controls) >= 0, "optimal_controls must be a list")
require(len(self.optimal_trajectory) >= 0, "optimal_trajectory must be a list")
```
`len()` always returns >= 0, so these checks are vacuous. They verify that the objects support `len()` but don't actually validate list content.

**Impact:** False sense of validation. The contracts appear thorough but don't actually catch invalid states.

**Fix:** Either check `len(...) > 0` if non-empty is required, or use `isinstance(self.optimal_controls, list)` if type checking is the intent.

**File:** `src/affine_control/swing_optimizer.py:181-187`
