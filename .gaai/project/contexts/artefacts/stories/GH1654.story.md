# GH1654: CI Black runs without --line-length 100, mismatches pyproject.toml

**Source:** D-sorganization/AffineDrift#1654

## Description

## Assessment: H. CI/CD (score 7/10)

**Finding:** The CI workflow `ci-standard.yml` runs `black --check .` without `--line-length 100`, but `pyproject.toml` specifies `line-length = 100` for `[tool.black]`. Black reads from pyproject.toml by default so this may work, but it creates a fragile implicit dependency. Additionally, CI pins `black==26.1.0` while `requirements.txt` has `black==26.3.1`, and similarly `ruff==0.14.10` in CI vs `ruff==0.15.6` in requirements.txt.

**Impact:** Version skew between CI and local development can cause format/lint disagreements.

**Fix:**
1. Explicitly pass `--line-length 100` in CI for clarity
2. Align tool versions between `ci-standard.yml` and `requirements.txt`
3. Consider using a shared constraints file

**Files:**
- `.github/workflows/ci-standard.yml` (lines 59, 43)
- `pyproject.toml` (line 109)
- `requirements.txt`
