# GH1663: RobotArm.linearize uses forward-difference instead of central-difference like other Hessian code

**Source:** D-sorganization/AffineDrift#1663

## Description

## Assessment: E. Performance / P2. Orthogonality

**Finding:** `src/tangent_models/examples.py` `RobotArm.linearize()` (line 318-348) uses forward finite differences `(f_pert - f0) / epsilon`, while the rest of the codebase (`_finite_diff_jacobian` in `residuals.py`) uses central differences `(f_plus - f_minus) / (2*epsilon)`. Forward differences have O(epsilon) error vs O(epsilon^2) for central differences.

**Impact:** Inconsistent numerical accuracy. The RobotArm linearization is less accurate than it could be, and the inconsistency suggests the code was written independently rather than reusing the existing Jacobian utility.

**Fix:** Either reuse `_finite_diff_jacobian` from `residuals.py` or switch to central differences for consistency.

**Files:**
- `src/tangent_models/examples.py:332-339`
- `src/affine_control/residuals.py:59-85`
