# GH1697 Execution Plan

## Story

**Title:** [Fleet Assessment][A] Oversized files are accumulating architectural responsibility

**Acceptance Criteria:**
1. The issue described in #1697 is resolved
2. All new code has tests (TDD)
3. `ruff check` passes on modified files
4. No new `print()` calls in `src/`
5. PR created targeting `staging` branch with clear description

## Problem Analysis

The fleet assessment identified files exceeding responsible size boundaries. The oversized
files flagged (package-lock.json, .qmd, .csl, .tex, .html articles) are either:
- Auto-generated (package-lock.json) — exempt from splitting
- Third-party citation style files (.csl) — not modifiable
- Article/content files (.qmd, .tex, .html) — splitting requires product-scope decisions

However, the underlying root cause is that the `module_size_budget.json` CI tooling had
**duplicated inline limit-resolution logic** in two places:
- `scripts/check_module_size_budget.py` (inline if/else logic)
- `scripts/check_changed_file_size_budget.py` (duplicated inline if/else logic)

This duplication means changes to limit-resolution policy must be made in two places —
a DRY violation that creates hidden coupling and change risk.

## Implementation Plan

### Step 1 — Extract `resolve_line_limit()` into `budget_check_utils.py`

Add `resolve_line_limit(rel, suffix, explicit_limits, max_by_ext) -> int | None` to
`src/tools/utils/budget_check_utils.py`, extracting the duplicated inline logic into a
single canonical function.

### Step 2 — Update `check_module_size_budget.py`

Replace the inline if/else limit resolution with `resolve_line_limit()`.

### Step 3 — Update `check_changed_file_size_budget.py`

Replace the inline if/else limit resolution with `resolve_line_limit()`.

### Step 4 — Add tests for `resolve_line_limit()`

Add `TestResolveLineLimit` class to `tests/test_budget_check_utils.py` with 5 test cases:
- Explicit limit takes precedence over extension limit
- Falls back to extension limit when no explicit limit
- Returns None when no limit applies
- Case-insensitive extension lookup
- Empty explicit limits uses extension lookup

## Files Affected

| File | Change |
|------|--------|
| `src/tools/utils/budget_check_utils.py` | Add `resolve_line_limit()` function |
| `scripts/check_module_size_budget.py` | Use `resolve_line_limit()` instead of inline logic |
| `scripts/check_changed_file_size_budget.py` | Use `resolve_line_limit()` instead of inline logic |
| `tests/test_budget_check_utils.py` | Add `TestResolveLineLimit` test class (5 tests) |

## Risk Assessment

Low. This is a pure DRY refactor with no behavior change — the extracted function
produces identical results to the inline logic it replaces. Tests validate all branches.
