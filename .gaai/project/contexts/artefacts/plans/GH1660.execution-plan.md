# GH1660 Execution Plan: Refactor Long Functions and Oversized Files

## Story Summary

Refactor 17 functions exceeding 50 lines and reduce 3 files exceeding 400 lines.
All new or modified code must have tests; ruff check must pass; no new print() calls.

## Tier

Tier 2 — Core Team (complexity ~5: multiple files, refactoring, TDD required)

## Approach

Extract helpers from long functions to bring each below 50 lines. For oversized files,
reduce line counts by extracting helper functions (which naturally shrinks the source
file). No architectural changes: no new modules created, no public API changes.

Approach evaluation: Not triggered. This is a well-established refactoring pattern
(function extraction) with no technology choices or new dependencies.

## Edge Cases

- `@st.cache_resource` decorators must be preserved on the original public functions
- Functions with `# type: ignore` annotations must preserve those comments
- No new `print()` calls — use logger
- No changes to public function signatures (backward compatibility)
- `_wrap_aside` has `check_already_wrapped` keyword-only param — preserve it

## Test Checkpoints

1. After each file modification: `python3 -m ruff check {file}` — zero violations
2. After all changes: `python3 -m pytest tests/ -x -q --tb=short` — all pass
3. Check function line counts: all < 50 lines
4. Check file line counts: all files ≤ 400 lines (or document why not)

## Risk Register

| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| Streamlit cache invalidation from refactor | Low | Keep `@st.cache_resource` on public functions only |
| Test breakage from private function restructure | Low | No public API changes |
| `ruff` violations from new helpers | Low | Follow existing code patterns |
| File size not reducible below 400 | Medium | Document and explain; AC1 is function threshold primary |

## Rollback Boundaries

- Each file is independently refactorable; rollback at file granularity
- Public API unchanged; no rollback needed for callers
