# GH1658 Execution Plan: DRY — Extract shared batch_convert utility

## Story Summary

`convert_all_latex.py` and `convert_all_to_quarto.py` contain a nearly identical
file-conversion loop (dry_run check, logging, try/except around `converter.convert_file`).
Extract a shared `batch_convert(converter, file_pairs, dry_run, logger)` function so the
loop lives in one place.

## Tier

Tier 2 — Core Team (complexity 2–3: 2 source files + 1 utils file modified, TDD required)

## Approach

Approach evaluation not triggered: this is a well-established extract-function DRY pattern
with a single obvious implementation. No new dependencies, no architectural choices.

## Implementation Sequence

### Phase 1: Create `src/tools/utils/conversion_utils.py`

New module containing:

```python
def batch_convert(converter, file_pairs, dry_run, logger):
    """Run a batch file conversion loop.

    Args:
        converter: Object with a convert_file(source, target) method.
        file_pairs: Iterable of dicts with "source" and "target" string keys.
        dry_run: If True, log what would be done without calling convert_file.
        logger: Logger instance for progress and error messages.

    Returns:
        True if all present source files converted without error, False otherwise.
    """
```

The implementation:
- Iterates over `file_pairs`
- Validates source and target are strings (raises ValueError on invalid entry — DbC)
- Skips (with logger.warning) files whose source path does not exist; increments error_count
- In dry_run mode: logger.info "Would convert: %s -> %s", increments success_count
- In live mode: calls `converter.convert_file(source, target)`, catches
  `(FileNotFoundError, PermissionError, OSError, ValueError)`, logs error on failure
- Returns `error_count == 0`

Export `batch_convert` from `src/tools/utils/__init__.py`.

### Phase 2: Refactor `src/tools/convert_all_latex.py`

Replace the loop body (lines 49-73) in `convert_all()` with a call to `batch_convert`.

The file_pairs list is just `CONVERSIONS` (each entry has "source" and "target").
The description/root_page fields are ignored by `batch_convert` — that is fine.

Import `batch_convert` from `src.tools.utils`.

Keep the `dry_run` early-log ("Dry run mode") before calling `batch_convert`.

### Phase 3: Refactor `src/tools/convert_all_to_quarto.py`

Replace the loop body (lines 141-161) in `convert_all()` with a call to `batch_convert`.

The file_pairs list is `CONVERSIONS` (each entry has "source", "target", "description").
The description field is not used by `batch_convert` — that is fine.

Keep the `setup_articles_directory()` call, the `dry_run` early-log, and the
post-conversion `success_count` summary log (this needs to be preserved via the

Import `batch_convert` from `src.tools.utils`.

### Phase 4: Tests

Add `tests/tools/test_conversion_utils.py` with tests for `batch_convert`:
- `test_dry_run_empty_list` — returns True on empty input
- `test_dry_run_with_existing_source` — logs "Would convert", does not call convert_file
- `test_dry_run_with_missing_source` — returns False, calls logger.warning
- `test_live_conversion_success` — calls convert_file, returns True
- `test_live_conversion_failure` — convert_file raises OSError, returns False
- `test_invalid_entry_type` — source is not a string, returns False

### Phase 5: Update existing tests

Existing tests in `test_convert_all.py` and `test_convert_all_to_quarto.py` must
continue to pass unchanged (no public API changes — convert_all() signature unchanged).

## Edge Cases

- `convert_all_to_quarto.py` has a post-conversion log: "Successfully converted %d files".
  After refactoring, success_count is internal to batch_convert. Since this is a debug log
  only (not a return value or behaviour), it can be dropped from the quarto converter — the
  function return value (True/False) is what callers depend on. Alternatively, the log can
  be moved to after the batch_convert call (always log if not dry_run). Keep it simple:
  move the log outside of batch_convert, letting the caller log after the call if desired.
  Simplest: remove it from convert_all_to_quarto.py (it was a nice-to-have info log, not a
  contract). The convert_all_latex.py version did not have this log. This is within scope
  (not a behaviour change for callers).

- Both source files import `from src.tools.utils import setup_logging` — this import path
  remains valid; add `batch_convert` to the same import line.

- `convert_all_latex.py` checks `not isinstance(source, str) or not isinstance(target, str)`
  before checking `os.path.exists`. The extracted `batch_convert` must preserve this guard
  (handled via DbC validation returning False + error_count increment).

- `convert_all_to_quarto.py` does NOT have the isinstance guard. After extraction,
  batch_convert will apply it to both callers uniformly. This is a safe improvement and
  within DRY scope (not a scope change — it's equivalent or stricter validation).

can inline the loop again. No schema, API, or public function signature changes.
