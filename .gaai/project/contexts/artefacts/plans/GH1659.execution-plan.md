# GH1659 Execution Plan: DDP mock is non-functional prototype left in production code

## Summary

Gate the non-functional DDP mock behind a properly-labeled implementation with runtime
`warnings.warn()` so that callers (including `SwingOptimizer`) are explicitly informed
at runtime that results are not mathematically meaningful. Clean up prototype comments.
Add tests verifying the warning fires.

## Approach Rationale

The story offers two paths: implement full DDP or gate behind `MockDDP` with warnings.
Full DDP is out of scope (requires backward pass / Riccati solving — large scope change).
The gating approach is the minimal compliant fix: retain the skeleton, add a clear
`warnings.warn(UserWarning)` so any caller is notified the output is a prototype.
The function name `adaptive_timestep_ddp_mock` already signals "mock" — the missing
piece is a runtime warning.

## Files to Modify

| File | Change |
|------|--------|
| `src/affine_control/ddp.py` | Add `import warnings`; add `warnings.warn()` at start of `adaptive_timestep_ddp_mock`; clean up prototype comments |
| `tests/test_affine_control/test_ddp.py` | Add test verifying UserWarning is emitted |

## Implementation Steps

### Step 1: `src/affine_control/ddp.py`

1. Add `import warnings` to stdlib imports (alphabetical order, before `from collections...`).
2. Add a module-level constant `_DDP_MOCK_WARNING` with a descriptive message.
3. In `adaptive_timestep_ddp_mock`, add `warnings.warn(_DDP_MOCK_WARNING, UserWarning, stacklevel=2)` as first statement after docstring.
4. Replace `# Simple Euler for prototype` comment with `# Euler integration (mock approximation — full RK4 not implemented)`.
5. Remove `# Break early for prototype` comment logic; replace with `# Mock: cap at 3 iterations` to make intent explicit.
6. Replace `# For robust implementation, use scipy.interpolate.interp1d` with `# Zero-order hold interpolation (mock implementation)`.
7. Remove `# Here we just map indices roughly for prototype without dependencies` line.

### Step 2: `tests/test_affine_control/test_ddp.py`

1. Add `import warnings` to imports.
2. Add `TestAdaptiveDDPMockWarning` class with test `test_emits_user_warning` that calls `adaptive_timestep_ddp_mock` inside `warnings.catch_warnings()` / `warnings.simplefilter("always")` and asserts at least one `UserWarning` is raised matching the mock warning text.

## Edge Cases

- Existing tests import `adaptive_timestep_ddp_mock` by name — keep that name, no rename.
- `swing_optimizer.py` also calls `adaptive_timestep_ddp_mock` — the warning will surface there too, which is intentional (it's the production caller that should be warned).
- `tests/test_dbc_application_contracts.py` calls the function multiple times in contract tests — those calls will also emit warnings; use `warnings.catch_warnings()` to suppress in existing contract tests if they fail due to warning noise. Check first.
