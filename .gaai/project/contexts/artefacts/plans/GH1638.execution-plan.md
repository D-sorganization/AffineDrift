# GH1638 Execution Plan: Standardize Logging Across src/tools

## Summary

Add `import logging` and `logger = logging.getLogger(__name__)` to every Python
file in `src/tools/` that does not already use the logging subsystem.
The project already has a `setup_logging` utility in `src/tools/utils/logging_utils.py`
exported via `src/tools/utils/__init__.py`. The established convention seen in
files like `check_site_health.py` and `update_navigation.py` is:

```python
from src.tools.utils import setup_logging
logger = setup_logging(__name__)
```

For utility modules and library code (not CLI entry points), the lighter-weight
stdlib pattern `logging.getLogger(__name__)` is acceptable — it does not configure
handlers and obeys the library logging best-practice (NullHandler by default).

**Decision:** Use `import logging` + `logger = logging.getLogger(__name__)` for
all non-CLI files. For top-level CLI scripts that are also missing logging, use the
`setup_logging` convention already established.
