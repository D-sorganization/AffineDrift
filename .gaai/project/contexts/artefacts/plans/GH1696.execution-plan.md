# GH1696 Execution Plan — Operational Output Consistency

## Story Summary
Standardize operational output across the codebase: `src/` must use structured
logging only; intentional CLI UX in `scripts/` may retain `print()`. Add a
CI enforcement gate so the constraint is maintained automatically.

## Approach
Use AST-based detection (not grep/regex) to find actual `print()` function call
nodes in `src/`. This avoids false positives from string literals like
`"print("` that appear in `analysis_utils.py`.

## Implementation Steps

### Step 1 — Create `scripts/check_logging_consistency.py`
- Walk all `.py` files under `src/`
- Parse each file with `ast.parse`
- Find `ast.Call` nodes where `func` is `ast.Name(id='print')` or
  `ast.Attribute(attr='print')` (covers all print() forms)
- Exclude false positives: string literals, comments
- Report violations; exit 1 if any found, exit 0 if clean

### Step 2 — Add CI step in `.github/workflows/ci-standard.yml`
- Insert after the `Verify DRY Shared-Helper Adoption` step
- Step name: `Verify Logging Consistency (no print in src/)`
- Command: `python3 scripts/check_logging_consistency.py`

### Step 3 — Create `tests/test_check_logging_consistency.py`
- Test: clean `src/` → checker returns 0
- Test: file with print() → checker returns 1 with correct violation
- Test: file with `"print("` string literal → NOT flagged (false positive guard)
- Test: file with `sys.stdout.write` → NOT flagged (out of scope for this AC)

## Edge Cases
- `analysis_utils.py` line 278: `"print("` as string literal — must NOT be flagged
- `__init__.py` files with no code — must not error
- Files with syntax errors — graceful skip with warning
- Scripts/ directory — explicitly excluded from check

## Test Checkpoints
- `pytest tests/test_check_logging_consistency.py` — all pass
- `python3 scripts/check_logging_consistency.py` — exits 0 (no violations in src/)
- `ruff check scripts/check_logging_consistency.py tests/test_check_logging_consistency.py` — clean

## Risk Register
- LOW: AST parse errors on unusual Python syntax — mitigated by graceful error handling
- LOW: False positive on string literals — mitigated by AST node inspection (not regex)

## Rollback Boundary
If CI step causes noise: remove the step from ci-standard.yml and the script.
No existing code is modified; rollback is additive-only.
