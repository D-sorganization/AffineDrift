## Technical Details

### deploy-website.yml

Root cause: The `Verify frontend asset sync --check` step ran before `quarto render`. Since
`docs/css/` and `docs/js/` are only created during Quarto render, the check always reported
11 MISSING MIRROR errors. Fix: moved the step to immediately after `Render Website`, where
`docs/` is fully populated.

### ci-standard.yml E2E job

Root cause: E2E tests were gated by `if [ -f "docs/index.html" ]`, which was always false
since docs/ HTML is never committed. The comment in the old code stated this was "intentional"
and tests would run post-deploy. This left zero E2E coverage in PR validation.

Fix: Added Quarto setup + render steps to the E2E job using the same action versions as
`deploy-website.yml` (`quarto-dev/quarto-actions/setup@v2` v1.6.39 and `/render@v2`). Added
`pip install -r requirements.txt` (needed for Python cells in QMD files) and `rm -f .env.example`
(same pattern as deploy job — prevents dotenv validation error). Increased `timeout-minutes`
from 8 to 20 to accommodate render time. Removed the conditional guard entirely.

## Rules Applied

- No new `print()` in `src/`
- `ruff check` clean
- No scope changes or product changes
- YAML validated (Python `yaml.safe_load` parse)

## Risks / Limitations

- Quarto render in E2E job adds ~5–15 minutes to E2E CI wall time. This is the documented
  trade-off for having reliable E2E smoke test coverage in PR validation.
- If Quarto render itself has failures (broken QMD syntax, missing resources), the E2E job
  will fail on render — this is a correct failure signal, not a regression.
