## 2024-05-23 - Unsanitized HTML Injection in Custom Build Script
**Vulnerability:** The `build-html.py` script injected `title` and `description` from `.qmd` YAML frontmatter directly into the HTML template without escaping. This allowed Cross-Site Scripting (XSS) via malicious metadata in source files.
**Learning:** Custom build scripts for static sites often lack the automatic sanitization features present in mature frameworks like Quarto or Jekyll. Input from source files (even "trusted" ones) should still be sanitized to prevent accidental markup breakage or injection.
**Prevention:** Always use `html.escape()` when injecting strings into HTML templates, even for build-time tools. Added strict typing and linting checks to the script.

## 2024-05-23 - Reverse Tabnabbing via Missing `rel="noopener noreferrer"`
**Vulnerability:** External links generated by JavaScript functions and Python template utilities (e.g. `latex_utils.py` and `bibliography.js`) used `target="_blank"` without proper `rel="noopener noreferrer"` attributes. This exposes the application to reverse tabnabbing attacks, allowing newly opened tabs to hijack the original tab via `window.opener`, and leaks referrer information.
**Learning:** Security attributes must be enforced consistently across all dynamic content generation methods, including string interpolation in JS and regex replacements in Python. Centralized utility functions are prime locations for introducing (or fixing) widespread vulnerabilities.
**Prevention:** Always append `rel="noopener noreferrer"` to any `<a>` tag utilizing `target="_blank"`, especially when constructing HTML programmatically. Implement linting rules or automated checks to ensure these attributes are present on external links.
## 2024-04-02 - Code Injection in MATLAB Quality Check
**Vulnerability:** In `src/tools/matlab_utilities/scripts/matlab_quality_check.py`, `script_path` was used directly in `run('...path...')` with single quote escaping which isn't fully safe against all edge cases. Using `script_path.stem` is also not viable as valid file names like `a-b.m` would be treated as subtraction. The safer approach relies on making sure the filename contains only safe characters, or using alternative methods to execute a file. Note: The attempt to fix it introduced another issue, highlighting the difficulty of dynamic script execution.
**Learning:** Using `script_path.stem` dynamically without quotes can cause valid filenames like `my-script.m` to be interpreted as subtraction (`my - script`) and actually allows command injection if the filename is malicious. When executing MATLAB/Octave scripts, always validate the filename or rely on standard safe mechanisms.
**Prevention:** Rather than string manipulation in `f"run('{safe_path}')"`, we must properly sanitize or ensure file names are safe beforehand, or use proper APIs when possible to execute scripts.
## 2024-04-02 - Code Injection False Positive
**Vulnerability:** I thought there was a code injection in `matlab_quality_check.py` because `replace("'", "''")` was used to escape single quotes, but MATLAB string literals actually don't parse backslash escapes inside single-quoted strings, and doubling single quotes is the robust and correct way to escape strings in MATLAB. Attempting to strip characters like semicolons or quotes creates a regression as legitimate paths with quotes or semicolons would break.
**Learning:** MATLAB's string escaping rules inside single quotes are extremely simple (doubling the quote). There's no backslash escaping, and newlines cause parse errors rather than code execution. Thus `run('path_with_escaped_quotes')` is fully secure.
**Prevention:** Do not try to "fix" robust language-specific string escaping mechanisms by replacing them with aggressive character stripping, as it degrades functionality without adding security.

## 2026-03-10 - Missing aria-hidden on decorative SVGs
**Vulnerability:** Missing `aria-hidden="true"` on dynamically injected SVG icons inside buttons and links. This can cause screen readers to announce the SVG contents or generic "image" terms alongside the parent's `aria-label`, leading to redundant and confusing announcements for users relying on assistive technology.
**Learning:** Decorative SVG icons inside interactive elements like buttons or links need explicit ARIA hiding so that assistive technologies focus solely on the meaningful text or the explicitly provided `aria-label` of the parent element.
**Prevention:** Always add `aria-hidden="true"` to dynamically injected decorative SVG icons during frontend DOM generation.
