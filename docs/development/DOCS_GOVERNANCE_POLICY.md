# Documentation Governance Policy

## Purpose

This policy defines the canonical structure for assessment reports, audit outputs, and generated documentation to prevent documentation sprawl and maintain a clear source of truth.

## Canonical Assessment Structure

All assessment and report artifacts follow this directory layout:

```
docs/assessments/
├── current/                     # Latest assessment results (overwritten each run)
│   ├── comprehensive_assessment.md
│   ├── implementation_plan.md
│   └── summary.md
├── archive/                     # Date-stamped archives of past assessments
│   └── YYYY-MM-DD/
│       ├── comprehensive_assessment.md
│       ├── implementation_plan.md
│       └── summary.md
├── issues/                      # Individual tracked issues (canonical references)
│   └── ISSUE_*.md
└── index.md                     # Auto-generated index of all assessments
```

## Rules

### 1. Source of Truth

- `docs/assessments/current/` is always the canonical latest assessment.
- Date-stamped files at root level (e.g., `comprehensive_assessment_2026-02-14.md`) are deprecated. New assessments must be placed in `current/` and archived upon replacement.

### 2. Archival Policy

- When a new assessment runs, the previous `current/` contents are moved to `archive/YYYY-MM-DD/`.
- Archives older than 90 days may be pruned by maintainers.
- Issue files in `issues/` are never archived; they are closed when resolved.

### 3. Report Generation

- All generated reports must include a `Generated:` timestamp in their frontmatter.
- Reports must not duplicate content that exists in source `.qmd` files.
- The `docs/` directory is a build artifact for Quarto output; non-Quarto content in `docs/development/` is the exception for developer guides.

### 4. Stale Reference Detection

The CI pipeline includes a check for stale assessment references:
- Links to `docs/assessments/` paths that no longer exist are flagged.
- References to date-stamped assessment files at root level are flagged as deprecated.

### 5. Index Maintenance

- `docs/assessments/index.md` is regenerated by `scripts/generate_assessment_summary.py`.
- Manual edits to the index are overwritten on the next assessment run.

## CI Integration

Add to `.github/workflows/ci-standard.yml` quality-gate job:

```yaml
- name: Check stale assessment references
  run: python3 scripts/check_stale_assessment_refs.py
```

## Ownership

- Assessment automation: `scripts/assess_repo.py`, `scripts/run_assessment.py`
- Issue creation: `scripts/create_issues_from_assessment.py`
- This policy: Maintainers review quarterly.
