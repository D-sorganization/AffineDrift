## Executive Findings

The repository has several distinct systems that use the word “matching.” The most physically direct work is the Simscape golf research track and the newer OpenSim full-swing tracking qualification track. The Simscape matching tree also has executable direct optimizers and shared fit/simulation pipeline code, while its README still calls the entire tree greenfield. Neural matching in `docs/plans/neural_motion_matching` has rigorous task/data/promotion contracts but explicitly has not trained models or measured speed. Shadow Tracker has implemented fit/evaluation architecture, but its own rules require fresh continuous forward replay and physics audits before a dynamics claim. Drake/OpenSim/Pinocchio/MuJoCo have polynomial-torque fitters and forward simulators, but their synthetic recovery tests are software evidence, not capture-level physical validation.

There is not one canonical, end-to-end “forward dynamics matches measured human kinematics” product in a qualified state. The repo already contains useful ingredients: marker/club loaders; FK/IK; position, orientation, velocity and torque/work costs; bounded direct and gradient-based fitters; surrogate/inverse-learning research; model scaling and adapters; tracking with continuity/contact/dynamic replays; and native audit receipts. The key research gap is identifiability and qualification: observed kinematics do not identify unique internal torques, inertial parameters, contact forces, or model dimensions. A learned-dimension adaptive model must expose uncertainty and confounding, and must be accepted only after held-out geometric validation and independent open-loop replay.

## Scaling, Anthropometry and Model Dimension Learning

OpenSim exposes `tour_matching/scale.py` and `segment_scaling.py`; tests `tests/opensim/test_segment_scale.py` plus `tests/integration/anthropometrics/` validate scaling/published tables/cross-engine round trips. Drake’s `motion_matching/humanoid_urdf.py` contains `DimensionEntry`, `HumanoidDimensions` and URDF model generation/loading. Shared anthropometry tools/tests exist. These support selecting/scaling body dimensions, but are not equivalent to an adaptive identification method that infers dimensions from a single time series jointly with controls, inertias, marker placements and contact.

This distinction matters because geometry, camera extrinsics, marker offsets, mass/inertia, actuator gains and torque profiles can compensate for each other. A dimension learner needs informative priors, parameter grouping, physical bounds, sensitivity/observability analysis, multi-view or multi-task evidence, held-out markers/time segments, and uncertainty. It should not freely expand topology or body DOFs to reduce residuals. Treat dimensions as a low-dimensional, structured latent with prior covariance; fit calibration/geometry first, then dynamics with geometry fixed or alternating under explicit identifiability checks. Enforce anthropometric ratios and positive segment inertias; tie mass/inertia to a documented density/subject-mass model. Add model complexity penalties and detect rank-deficient Fisher/Jacobian directions. If data cannot identify a dimension, report it as prior-dominated/unobserved instead of “learned.”

## Research Design Gaps and Improvements to Prioritize

1. **Define a single evidence ladder.** Separate (a) visual pose/IK fit, (b) torque-driven tracking with feedback, (c) independent open-loop forward replay, (d) physical contact/dynamics qualification. Require target/reference/model hashes, runtime/release, units, coverage, objective components, solver termination, continuous replay, force/energy residuals, and acceptance gates for each tier.
2. **Canonicalize parameters and time.** Freeze a versioned coefficient schema including per-joint ordering, polynomial order and coefficient-to-power map, normalized time variable (e.g. τ=t/T to avoid coefficient scaling), units, bounds, controls versus torques, and cross-engine parity tests. Current engine defaults differ materially.
3. **Model identifiability, not just residual.** Derive local sensitivities of marker/club observations to control and model parameters; report singular values/null space and profile likelihood/bootstrapped intervals. Optimize observable parameter combinations; regularize or freeze unidentifiable coordinates.
4. **Jointly handle data validity and calibration.** Explicit masks for missing/occluded markers, robust losses, camera and marker offsets, coordinate frames, timing, filtering and derivative uncertainty. Avoid treating interpolated observations as measurements. Calibrate on some frames and report held-out frames/time periods.
5. **Extend objective beyond point positions.** Weight uncertainty-normalized positions and orientations on SO(3); use velocities/accelerations only with measurement-noise propagation; add contact consistency, torque/effort/work/smoothness and physical plausibility as separate reported terms. Avoid letting a single scalar obscure tradeoffs. Preserve Pareto or profile results.
6. **Use differentiable/learned components as proposals.** Surrogate and inverse network should generate candidate starts and uncertainty, not authority; validate candidates against the exact native simulator, reject OOD, retain direct optimizer as oracle, and track accepted-quality rate/calibration. Dataset split by capture/subject/model family, not adjacent frames.
7. **Adaptive dimensions with constrained complexity.** Introduce staged variables: camera/calibration; marker attachment/segment dimensions; dynamic masses/inertias; controls/torques. Use hierarchical anthropometric priors and global shared proportions, sparse updates, bounded trust regions and posterior uncertainty. Alternating optimization can avoid dimension-control co-adaptation; compare against fixed-dimension baseline and synthetic recovery with known truth.
8. **Numerical robustness and cost.** Normalize decision variables, use time-scaled bases (Chebyshev/B-spline or smooth basis with continuity constraints) in addition to monomial polynomial baseline; warm-start and multi-start; quantify simulator failures and penalty sensitivity. For long horizons use transcription/Moco/direct collocation where useful, then validate by independent replay.
9. **TDD/DbC/DRY/LoD review.** The code standards are specified in matching docs; verify actual public paths use input/output contracts and tests. Avoid interpreting tests against mocked simulator closures as live dynamics verification. Share objective/target/timebase/parameter schema across engines.

### How the Revised Finding Changes the Design Review

There is already a meaningful neural method portfolio: deterministic forward emulation, differentiable inversion, compact and per-step variants, multimodal inverse CVAE, deterministic inverse regression, per-step inverse dynamics, masked proposals and physics-structured correction. The next research question is comparative validity and observability, not choosing an architecture from scratch. Use one frozen dataset/model roster and evaluate these methods against identical trial-family held-outs, the same exact forward simulator, explicit OOD strata, and matched compute budgets. For a learned-dimension model, the current models generally assume a fixed `n_joints`/output topology and learn motion/control mappings; none by its interface should be described as learning skeletal/model dimensions unless explicit dimension parameters, priors and native structural validation are added.

A safe pipeline is: (1) construct versioned native episodes with controls, states, model identity, contact mode and full provenance; (2) train forward and inverse proposals under grouped splits; (3) report calibration, mode coverage, boundary/OOD performance and surrogate gradient fidelity; (4) optimize or polish using exact/native mechanics; (5) replay independently from the unchanged initial state; and (6) compare quality-matched accepted candidates against classical optimizers at measured end-to-end latency. Promote per model and control basis only. Keep software contracts, measured learned prediction, native replay, and physics qualification as separate statuses.
