## 2. API Conformance (Gymnasium 1.3.0)

- **Reset Protocol:** `obs, _ = env.reset(seed=seed)` matches Gymnasium 2-tuple `(obs, info)` signature.
- **Step Protocol:** `obs, reward, terminal, cutoff, _ = env.step(action)` correctly unpacks 5-element tuple: `(obs, reward, terminated, truncated, info)`.
- **Action Space Validation:** `env.action_space.contains(action)` validates shape, type, and $[-2, 2]$ bounds.
- **Defensive State Isolation:** `obs.copy()` and `action.copy()` safeguard array buffers against in-place mutations.
- **Resource Management:** `try...finally: env.close()` guarantees environment release.

## 3. Termination vs. Truncation and Bootstrap Mechanics

- **Task Mechanics:** `Pendulum-v1` has no intrinsic termination (`terminated=False`); episodes end purely via time limit (`truncated=True`).
- **Bellman Target Formulation:** 
  $$y_k = r_k + \gamma (1 - \mathbf{1}_{\mathrm{terminated}}) V(o_{k+1})$$
  - Truncation ($\mathrm{terminated}=\mathrm{False}$): bootstraps $V(o_{k+1})$.
  - True termination ($\mathrm{terminated}=\mathrm{True}$): zeroes out the continuation value.
- **Numerical Verification:** For $r=2$, $\gamma=0.9$, $V(o')=5$:
  - Truncated: $2 + 0.9 \times 5 = 6.5$.
  - Terminated: $2 + 0.9 \times 0 = 2.0$.
  Matches text and test assertions exactly.

## 4. Concrete Deficiencies & Gaps in Test Coverage

While the core functionality passes verification, the actual test suite contains the following specific gaps:

### Concrete Issue 1: Multi-Step Physical Integration Not Tested
- **Deficiency:** `test_run_pendulum_physics_and_reward` tests only `steps=1`. 
- **Impact:** It does not test the semi-implicit Euler state chain over consecutive steps (i.e. verifying that $\omega_1$ computed from $s_0, a_0$ is correctly used to advance $\theta_1 \to \theta_2$ on the subsequent transition, and that intermediate reward calculations track the evolving pre-step state).
- **Remediation:** Assert predictions across $\ge 2$ consecutive steps in `_predict_pendulum_step`.

### Concrete Issue 2: Angular Normalization Wrapping / Modulo Boundary Untested
- **Deficiency:** `test_run_pendulum_physics_and_reward` uses an initial state near upright with a small torque ($0.4$). It never exercises angles outside $[-\pi, \pi)$ where the wrap-around $\bar{\theta} = ((\theta + \pi) \pmod{2\pi}) - \pi$ affects the reward.
- **Impact:** An erroneous implementation of the angle normalization (e.g. standard modulo vs. symmetric shift) would pass this test suite.
- **Remediation:** Add a test verifying reward calculation on an observation near the $-\pi / \pi$ seam (downward position).

### Concrete Issue 3: Velocity Saturation (Clip at $\pm 8$) Not Exercised
- **Deficiency:** No test verifies the $[-8.0, 8.0]$ angular velocity clamping boundary during rollout execution.
- **Impact:** A divergence between integration models when $\omega$ exceeds magnitude 8 would go undetected.
- **Remediation:** Run a trajectory with maximal torque ($\tau = 2.0$) over sufficient steps to saturate $\omega$ at $8.0$ and verify that `rollout["observations"][:, 2]` strictly clamps at $8.0$.

### Concrete Issue 4: `numpy.bool_` Type Permissibility in `bootstrap_target`
- **Deficiency:** `test_bootstrap_target_invalid_domains` tests scalar floats and integer inputs, but does not test `np.bool_(True)` / `np.bool_(False)`.
- **Impact:** `bootstrap_target` specifically includes `isinstance(terminated, (bool, np.bool_))`, which is common when processing Gymnasium step returns into NumPy arrays, but this code path is unexercised in the test suite.
- **Remediation:** Add explicit parametrized assertions for `np.bool_(True)` and `np.bool_(False)`.
